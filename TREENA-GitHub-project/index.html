01
公开仓库交互式网页演示HTML · CSS · JAVASCRIPT

家教订单浏览器

面向老师的家教机会浏览工具，将结构化订单转化为可搜索、可筛选的信息界面。老师可按区域、科目、老师类型、授课时间与时薪筛选机会，并复制完整订单信息用于后续沟通。

  • 支持组合筛选、订单池切换、分页与无结果提示。
  • 采用响应式布局，提供移动端筛选面板。
  • 支持剪贴板复制及手动复制回退，展示区域与科目统计。
  • 另有面向家长与老师的公开服务指南，包含规范链接元数据、结构化数据与站点地图。
与 AI Agent 岗位的关联

结构化订单字段适合用于讲解自然语言意图提取、工具参数设计与可解释匹配。

后续可扩展方向

增加一个助手，将老师的自然语言偏好转为筛选条件，并解释推荐理由；订单是否可接及最终对接安排仍需确认。

当前边界：本次核查到的是浏览器演示页面，尚不能据此认定已有上线的智能匹配 Agent 或生产后端。

02
私有仓库 · 需访问权限业务流程管理NEXT.JS · PRISMA

TrademarkFlow 商标管理系统

根据仓库文档，这是一个使用 Next.js 实现的商标案件管理应用，将领域逻辑与存储适配分开组织，在统一界面中呈现案件阶段、进度、风险、优先级、负责人及下一步行动。

  • 总览仪表盘展示 7 项动态 KPI 与 P0/P1 优先事项。
  • 支持案件搜索与详情查看，展示阶段持续时间、剩余天数、风险原因、付款与证书状态。
  • 进度、风险与优先级由领域层统一计算，UI 和 API 消费计算结果。
  • 默认使用本地 JSON 持久化，幂等初始化 8 个演示案例；通过仓储接口与 Prisma/PostgreSQL 适配器支持后续切换存储。
与 AI Agent 岗位的关联

明确的业务规则与仓储边界，为受控工具访问、可追溯建议和业务数据查询提供基础。

后续可扩展方向

增加只读案件助手，检索当前记录、解释优先级，并提出交由人工确认的下一步建议。

02 / 个人介绍

“我擅长从业务问题出发，搭建 AI 工作流并持续迭代。”

面试官您好，我叫王慧，毕业于西南民族大学经济学专业。我的经历主要围绕业务需求分析、流程优化和 AI 应用落地展开。我想重点介绍三段实践。

首先是我自己搭建 AI Agent 和业务系统的过程。在家教星球项目中，我从订单分散、人工查单低效、多机构订单重复和归属不清等问题入手，先梳理业务流程、输出 PRD，再借助 AI 工具搭建网站和内部工作系统，把订单录入、筛选、跟进与结算串起来。在这个过程中，我也逐步积累自己的 Skill 库，把重复任务中的要求、步骤和检查标准整理成可复用指令，并通过原型测试持续调整。对我来说，搭建 Agent 的关键是先把任务拆清楚，再设计它需要的信息、执行步骤和结果检查方式。

第二段是在菲龙咨询做商标业务可视化。当时我在客户需求诊断和交付跟进中接触到多个业务节点，需要持续追踪进度、识别异常并协调推进。我主导搭建了商标数字化跟踪系统，将流程、节点和异常情况可视化，并结合知识沉淀与智能应答，形成业务跟进闭环。这段经历让我认识到，AI 要真正帮助业务，首先要有清楚的流程和可以持续维护的信息。

第三段是在三维家做 AI 产品应用与解决方案。我围绕 AI 梦想家、AI 轻设计等产品，调研泛家居企业在营销转化、设计提效和客户沟通中的需求，参与产品演示、应用测试和适配反馈。同时，我针对客户信息整理、线索筛选、需求分析、沟通策略和跟进管理这五类任务，设计多 Agent 协作方案，用 Prompt、Skill 和 Workflow 梳理执行逻辑，沉淀可复用模板。

所以，我希望在 AI Agent 岗位上发挥的优势，是理解业务、拆解任务，并把方案做成能够测试和迭代的工作流，持续推动 AI 在具体场景中落地。
